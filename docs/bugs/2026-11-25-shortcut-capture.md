# Linux 自定义快捷键无法开始录入（0.2.8）

## 原因

Windows 界面调用 `start_shortcut_capture` 和 `stop_shortcut_capture`，Linux 原生宿主未实现这两个命令；`subscribeShortcutCaptureEdges` 的 Linux 分支又是空订阅。开始接口报错后，前端不会进入录入状态，已有 DOM 键盘处理也无法工作。

## 修复

- GTK 主线程实现录入会话，通过当前窗口的按下/松开信号捕获快捷键，在 WebKit 默认处理及输入法处理前截获。
- 按未修饰的 GDK 键值识别字母、符号、左右修饰键、小键盘、功能和媒体按键；同一物理键的松开沿用按下时的名称，过滤重复按下。
- Linux 桥接订阅真实 `shortcut-capture-edge` 事件。沿用已有前端保存流程和安全模式。
- 开始前已经按住的键先放行至全部松开；取消后吞掉本会话按键的配对释放，避免将无按下的释放泄漏到 WebKit。失焦、超时、退出会结束会话。
- 只处理当前应用窗口的按键，不增加全局读取权限。Super、Alt+Tab 等被桌面截获的组合使用安全模式：在界面选择修饰键，仅在键盘上按主键。

## 验证

后端 46 项测试通过；前端 726 项通过、13 项跳过。独立配置下运行真实 GTK/WebKit 窗口：Ctrl+Shift+[ 保存、Win+L 安全模式、Esc 取消、失焦取消和配置重新读取均通过。另以 uinput 系统虚拟键盘实际发送按键重复上述验证，通过窗口焦点检查后才注入；同样全部通过。测试不修改用户按键映射。安装包版本为 0.2.8。
